# Документация в репозитории

В корне проекта есть каталог **`docs/`** — это markdown для команды, ведущей пакет: архитектура, гайды по процессам, справочники. Он **не** дублируется автоматически на этом сайте: файлы живут в git и удобнее всего читаются в IDE или в веб-интерфейсе репозитория.

## С чего начать

| Файл                   | Содержание                                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs/README.md`       | Оглавление: точки входа и внешние артефакты                                                                                                  |
| `docs/CONTRIBUTING.md` | Процесс (ветки, PR, релиз) и правила ведения документации: что куда писать, дерево связей                                                    |
| `docs/architecture/`   | Архитектура: паттерны инпутов, оверлеев, layout, стилей, тем (скины и контракты), сборки, адаптеров                                          |
| `docs/guides/`         | Гайды: установка, публикация, миграции, новый компонент, accessibility                                                                       |
| `docs/reference/`      | Справочники: каталог компонентов, sub-entry points, хуки, токены                                                                             |
| `docs/changes/`        | Внутренний лог изменений по месяцам (детально, для команды пакета)                                                                           |
| `docs/tech-debt/`      | Технический долг: известные проблемы, которые нужно решить, — по файлу на задачу (например, директива `'use client'` для Next.js App Router) |

Этот VitePress-сайт — публичное лицо проекта для команд, **подключающих** пакет. Внутренняя документация — для команды, **ведущей** пакет.
