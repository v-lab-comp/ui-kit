# Составные инпуты

## Что это и зачем

Бывает поле, где **одно значение** на самом деле из **двух кусков**. Например:

- Сайт: `https://` + `example.com`
- Телефон: `+998` + `901234567`
- Домен: `example` + `.com`

Пользователь видит их по отдельности (выбор протокола слева, ввод пути справа), но в форму уходит **одна строка** и при желании **отдельные части** (например протокол в своё поле для бэкенда).

Составной инпут — это как раз такой компонент: внутри несколько кусков, снаружи одно значение.

---

## Как это устроено (простыми словами)

1. **Хранится одна строка.** Вся «правда» — одна полная строка (`https://example.com`). Не два состояния (протокол и путь), а одно. Так ничего не разъедется.

2. **Части считаются из строки.** При каждом отрисовке строка **разбирается** на части: `split("https://example.com")` → `["https://", "example.com"]`. Части нигде отдельно не хранятся — только считаются. Поэтому нельзя случайно получить протокол от одного URL и путь от другого.

3. **Менять — только через «сборку».** Пользователь поменял путь. Ты вызываешь «собери части обратно в строку и обнови значение» — `notifyParts([текущийПротокол, новыйПуть])`. Хук сам склеивает строку и отдаёт её родителю и в скрытые поля формы.

4. **Форма получает и целое, и части.** Хук сам создаёт скрытые `<input type="hidden">`: один с полной строкой (`name="website"`), остальные — по желанию, по одной на часть (`name="protocol"` и т.д.). Бэкенду не нужно парсить — всё уже разложено по полям.

5. **Родитель общается одной строкой.** Снаружи компонент ведёт себя как обычный инпут: передаёшь `value` и `onChange` с одной строкой. То, что внутри есть части и скрытые поля — детали реализации.

---

## Как сделать свой составной инпут (по шагам)

### Шаг 1. Решить, из чего состоит значение

Например: «сайт = протокол + путь», «телефон = код страны + номер». От этого зависит, сколько частей будет в массиве.

### Шаг 2. Написать функцию «разобрать строку» (split)

На вход — одна строка, на выход — массив частей.

- Если строка правильная — режешь её по смыслу (например по регулярке протокола).
- Если неправильная или пустая — отдаёшь разумные значения по умолчанию: например дефолтный протокол и то, что пользователь ввёл, как «остаток».

Пример: `"https://example.com"` → `["https://", "example.com"]`, для мусора — `["https://", "то что ввели"]`.

### Шаг 3. Написать функцию «склеить части» (join)

На вход — массив частей, на выход — одна строка. Должно быть согласовано с split: склеил разобранное — получил исходное.

Пример: `["https://", "example.com"]` → `"https://example.com"`.

### Шаг 4. Вызвать хук

Передаёшь в `useCompositeInput`:

- `value` / `defaultValue`, `onChange`, `name` — как у обычного инпута;
- `split` и `join` — твои функции;
- `formNames` — если хочешь, чтобы какая-то часть уходила в форму отдельным полем (например `['protocol']` для первой части).

### Шаг 5. Вставить скрытые поля в разметку

В начале JSX пишешь `{hiddenInputs}`. Хук сам отрисует нужные `<input type="hidden">` — ничего больше делать не нужно.

### Шаг 6. Достать части для отображения

Из хука приходят `parts` — тот самый массив частей. Делаешь, например: `const [протокол, путь] = parts`.

### Шаг 7. Показать интерфейс

- В `InputField` через `startBlock` (или `endBlock`) показываешь одну часть — текст или селектор (например протокол).
- Внутри поля — `BaseInput`, в нём `value={путь}` (или другая часть).
- В `onChange` этого инпута вызываешь `notifyParts([протокол, новоеЗначениеПути])` — то есть «все части, но одну обновил». Хук сам склеит и обновит значение.

### Шаг 8. При любом изменении части — вызывать notifyParts

Не обновляешь state вручную. Всегда вызываешь `notifyParts([часть1, часть2, ...])` с полным набором частей (остальные берёшь из `parts`). Хук сам пересоберёт строку и отдаст её наверх и в скрытые поля.

**Минимальный каркас:**

```tsx
const { parts, notifyParts, hiddenInputs } = useCompositeInput({
  value,
  defaultValue,
  onChange,
  name,
  split: (str) => splitMyValue(str, fallback),
  join: (parts) => parts.join(''),
  formNames: ['part0'], // опционально — какая часть в какое поле формы
})

const [part0, part1] = parts

return (
  <>
    {hiddenInputs}
    <InputField startBlock={part0}>
      <BaseInput value={part1} onChange={(e) => notifyParts([part0, e.target.value])} />
    </InputField>
  </>
)
```

## Как задать значение и что уходит в форму

Ты **не прописываешь протокол и путь по отдельности**. Внешне у инпута одно значение — полная строка. Её и задаёшь.

### Что передавать в компонент

| Проп                     | Что это                                                                                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `value`                  | Полная строка (controlled). Например `"https://example.com"`. Компонент сам разобьёт на протокол и путь.                                                                         |
| `defaultValue`           | То же, но для uncontrolled — начальное значение полной строки.                                                                                                                   |
| `onChange`               | Вызывается с полной строкой `(value: string)` — уже склеенный URL, не части и не событие.                                                                                        |
| `name`                   | Имя поля формы. При submit в форму уйдёт одно поле с этим именем и полным значением.                                                                                             |
| `protocol` (у SiteInput) | Не «текущий протокол», а **дефолт**, если в строке протокола нет (например пользователь стёр всё). При `protocol="https://"` пустой ввод покажется как `https://` + пустой путь. |

Протокол и путь на экране **выводятся из одной строки** через `split`. Отдельно их в пропах не задаёшь.

### Примеры: как задать начальное значение

```tsx
// Неуправляемый инпут — начальное значение одной строкой
<SiteInput
  name="website"
  defaultValue="https://mysite.com"
  label="Сайт"
  protocol="https://"
  endBlock="/"
  hint="Протокол слева, суффикс / справа."
/>
// На экране: слева "https://", в поле "mysite.com", справа "/".
// В форме при submit: website="https://mysite.com"
```

```tsx
// Управляемый — хранишь одну строку в state
const [url, setUrl] = useState('https://example.com')
<SiteInput
  name="website"
  value={url}
  onChange={setUrl}
  label="Сайт"
  protocol="https://"
  endBlock="/"
/>
// url всегда полный URL; протокол и путь внутри считаются из неё.
```

### Отдельные поля в форме (protocol, path и т.д.)

Если нужны не только полное значение, но и части (например протокол отдельно для бэкенда), это настраивается **внутри компонента** через хук: `formNames: ['protocol']`. Тогда хук сам рендерит скрытые инпуты.

Для SiteInput это уже сделано: при `name="website"` и `formNames: ['protocol']` в форме при submit будут:

- `website` = полная строка, например `"https://mysite.com"`
- `protocol` = первая часть, например `"https://"`

Имена частей задаются в `formNames` по порядку: первый элемент — имя для `parts[0]`, второй — для `parts[1]`. Если часть не нужна отдельным полем — в массиве на её месте `undefined`.

```tsx
// Внутри компонента (например своего составного инпута):
formNames: ['protocol'] // parts[0] уходит в поле "protocol"
formNames: [undefined, 'tld'] // parts[1] уходит в поле "tld"
formNames: ['protocol', 'path'] // оба поля отдельно
```

Пользователь SiteInput ничего дополнительно не прописывает: передаёшь только `name`, а компонент уже настроен отдавать и `website`, и `protocol`.

### Кратко

- **Значение** — одна строка: `value` или `defaultValue` (полный URL, полный телефон и т.д.).
- **Протокол на экране** — не отдельный проп; он получается из этой строки. Проп `protocol` у SiteInput — только значение по умолчанию для пустого/некорректного ввода.
- **В форме** — поле `name` даёт полное значение; части вроде `protocol` появляются за счёт `formNames` внутри компонента.

## Пример: SiteInput (сайт = протокол + путь)

Визуально:

```
┌─────────────┬──────────────────┐
│ https://    │ example.com       │
│ startBlock  │ BaseInput         │
└─────────────┴──────────────────┘
```

При отправке формы: `website="https://example.com"`, при необходимости отдельно `protocol="https://"`.

Код:

```tsx
const { parts, notifyParts, hiddenInputs } = useCompositeInput({
  value,
  defaultValue,
  onChange,
  name,
  split: (url) => splitProtocol(url, 'https://'),
  join: ([proto, path]) => proto + path,
  formNames: ['protocol'],
})

const [currentProtocol, currentPath] = parts

return (
  <>
    {hiddenInputs}
    <InputField startBlock={currentProtocol}>
      <BaseInput
        value={currentPath}
        onChange={(e) => notifyParts([currentProtocol, e.target.value])}
      />
    </InputField>
  </>
)
```

## Динамические части: когда в блоке Select (или другой контрол)

Часть слева или справа может быть не статичным текстом, а выпадающим списком, кнопками и т.п. Хук от этого не меняется: он по‑прежнему хранит одну строку и даёт тебе массив частей. Ты просто подменяешь «текст в startBlock» на контрол и связываешь его с той же частью и с `notifyParts`.

### Как это работает по шагам

1. **Текущее значение части** ты уже получаешь из `parts` (например `currentProtocol`). Эту же величину передаёшь в Select как `value={currentProtocol}` — выпадающий список показывает актуальный выбор.

2. **Пользователь выбрал другой пункт** (например сменил `https://` на `http://`). В `onChange` Select приходит новое значение этой части. Остальные части не трогаем — берём из `parts` (например `currentPath`). `onChange(value)` SelectInput получает само значение — вызываешь `notifyParts([value, currentPath])` — «новая первая часть, вторая без изменений».

3. **Хук делает то же, что и при вводе в инпут:** склеивает части через `join`, получает новую полную строку, обновляет внутреннее значение и вызывает `onChange` с этой строкой. На следующем рендере `split(composedValue)` даёт уже обновлённые части — Select получит новый `currentProtocol` и отобразит его.

4. **Итого:** для хука нет разницы, изменилась часть из инпута или из Select. Всегда один и тот же сценарий: «вот новый массив частей» → `notifyParts(новыеЧасти)` → хук склеивает и обновляет. Контрол в `startBlock`/`endBlock` только отображает одну часть и при изменении вызывает `notifyParts` с подставленной новой этой частью.

### Пример: SiteInput с выбором протокола (Select в startBlock)

Вместо статичного `startBlock={currentProtocol}` рендерится Select. В него передаётся текущая часть как `value`, при смене опции — `notifyParts([новыйПротокол, currentPath])`:

```tsx
const defaultProtocol = protocolOptions?.[0]?.value ?? 'https://'

const { parts, notifyParts, hiddenInputs } = useCompositeInput({
  value,
  defaultValue,
  onChange,
  name,
  split: (url) => splitProtocol(url, defaultProtocol),
  join: ([proto, path]) => proto + path,
  formNames: ['protocol'],
})

const [currentProtocol, currentPath] = parts
const fieldId = id ?? generatedId // тот же id уходит в InputField — от него id элемента label

const startBlock = protocolOptions ? (
  <SelectInput
    variant="inline"
    // у inline нет видимой подписи — имя обязательно: своя подпись → label поля → подпись опции
    {...compositeSelectName({
      ariaLabel: protocolAriaLabel,
      labelId: label ? inputFieldLabelId(fieldId) : undefined,
      fallbackLabel: protocolOptions.find((o) => o.value === currentProtocol)?.label ?? currentProtocol,
    })}
    options={protocolOptions}
    value={currentProtocol}
    onChange={(nextProtocol) => notifyParts([nextProtocol, currentPath])}
    size={size}
    disabled={disabled}
    placement="bottom"
  />
) : (
  currentProtocol  // статичный текст, если опций нет
)

return (
  <>
    {hiddenInputs}
    <InputField id={fieldId} startBlock={startBlock} ...>
      <BaseInput
        value={currentPath}
        onChange={(e) => notifyParts([currentProtocol, e.target.value])}
        ...
      />
    </InputField>
  </>
)
```

- **Select `value`** — всегда текущая часть из `parts`, чтобы отображалось то, что лежит в общей строке.
- **Select `onChange`** — собираем новый массив частей (выбранное в Select + остальные из `parts`) и вызываем `notifyParts`. Дальше хук обновляет строку и при следующем рендере `parts` уже содержат новый протокол.
- **Имя Select** — `compositeSelectName` (рядом с хуком, в `useCompositeInput.ts`): подпись от приложения (`protocolAriaLabel` / `countryAriaLabel`), иначе `aria-labelledby` на label поля, иначе `aria-label` с подписью выбранной опции. Новых текстов не добавляет. `aria-labelledby` на сам триггер не подходит: у combobox, на который ссылаются, имя берётся из выбранного пункта списка, а не из текста кнопки.

То же самое можно сделать для части справа (`endBlock`): например, Select зоны домена — `value={currentTld}`, `onChange={(nextTld) => notifyParts([currentName, nextTld])}`.

## Пример: телефон (код страны + номер)

Разбор: `split(phone)` возвращает `[код, номер]`, для некорректной строки — fallback кода и весь ввод как номер. Сборка: `join([код, номер])` — склеить через пробел или как нужно.

```tsx
const { parts, notifyParts, hiddenInputs } = useCompositeInput({
  value,
  defaultValue,
  onChange,
  name,
  split: (phone) => splitPhone(phone, '+998'),
  join: ([code, number]) => code + ' ' + number,
  formNames: ['countryCode'],
})

const [code, number] = parts

return (
  <>
    {hiddenInputs}
    <InputField startBlock={селекторКода}>
      <BaseInput value={number} onChange={(e) => notifyParts([code, e.target.value])} />
    </InputField>
  </>
)
```

Форма получит полный номер в основном поле и отдельно `countryCode`, если это задано в `formNames`.

## Часть справа (endBlock) и formNames

Если «вторая часть» показывается справа (например домен `example` и зона `.com`), используй `endBlock` у `InputField`: туда передаёшь селектор зоны, в инпуте — значение без зоны.

В `formNames` можно указать, какие части уходят в форму отдельно. Порядок как у частей: первый элемент — для `parts[0]`, второй — для `parts[1]`. Если какую-то часть не нужно отправлять отдельным полем — ставь `undefined` на этом месте. В основное поле с `name` всё равно попадёт полная склеенная строка.

Пример: домен разбит на `["example", ".com"]`, в форму нужна только зона: `formNames: [undefined, 'tld']` — в форму уйдёт `name="example.com"` и отдельно `tld=".com"`.

## Кратко: что помнить

- Снаружи компонент — как обычный инпут: одна строка в `value`/`onChange`.
- Внутри хранится одна строка; части каждый раз считаются через `split`.
- Менять значение — только через `notifyParts([...части])`; хук сам склеит и обновит всё.
- Скрытые поля для формы хук создаёт сам — достаточно вставить `{hiddenInputs}` в JSX. Разметку строит `formFields` (тот же модуль): ему можно передать объект `{ имя: значение }` или массив пар `[имя, значение]` — массив сохраняет порядок и повторяющиеся имена.
- С react-hook-form достаточно работать через `value`/`onChange` одной строкой; скрытые поля нужны только для нативной отправки формы.
