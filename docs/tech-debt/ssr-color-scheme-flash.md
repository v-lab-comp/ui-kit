# Мигание сохранённой тёмной схемы при SSR

**Статус:** открыто · **Приоритет:** низкий · **Заведено:** 2026-11-10

## Текущая ситуация

`ThemeProvider` с `storageKey` хранит выбор пользователя в `localStorage`. Сервер его не видит, поэтому серверный `<html>` (через `themeHtmlAttributes(skin, 'light')`) отдаёт светлую схему, а после гидрации провайдер переключает на сохранённую тёмную — на первом кадре страница мигает светлой. То же для `defaultColorScheme="system"`: системную настройку сервер тоже не знает.

## Целевое состояние

Первый кадр сразу в нужной схеме. Обычное решение (так делает `next-themes`): маленький инлайн-скрипт в `<head>`, который до первой отрисовки читает `localStorage` / `prefers-color-scheme` и ставит `data-vl-scheme` и `data-theme` на `<html>`. Альтернатива — хранить выбор в cookie и читать его на сервере.

## Trade-offs

- **Выигрываем:** нет вспышки светлой темы у пользователей с тёмной.
- **Риски:** инлайн-скрипт требует CSP `script-src` с nonce/hash; логика чтения хранилища дублируется в скрипте и в провайдере — их нужно генерировать из одного места.

## Сценарий миграции

- Шаг 1: экспортировать функцию, возвращающую текст инлайн-скрипта для `storageKey` (формат хранилища — как в `ThemeProvider`).
- Шаг 2: пример для Next.js (`app/layout.tsx`) и общий для SSR в гайде установки; учесть `suppressHydrationWarning` на `<html>`.
- Шаг 3: тест: сохранённая `dark` в `localStorage` → атрибуты стоят до гидрации.
- Откат: удалить экспорт; приложения без скрипта работают как сейчас.

## Метрики успеха

- При сохранённой тёмной схеме первый кадр тёмный (проверка в Playwright со снимком до гидрации).
