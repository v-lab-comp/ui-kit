# [2026-09-17] PhoneInput: вставка номера, синхронизация страны, выделение, значения не в E.164

### Что изменено

**Fixed**

- **Вставка номера с кодом страны.** `+998 90 123 45 67` / `998901234567` раньше превращались в `+998998901234` (библиотека считала все цифры национальной частью, цикл обрезки `TOO_LONG` срезал хвост). Теперь `onPaste` разбирает текст через `parseFullPhone`, заменяет поле целиком и переключает страну (`+7 912 345 67 89` → RU, если разрешена). Номер неразрешённой страны игнорируется. Та же попытка разбора — в `onChange`, когда цифр добавилось больше одной и номер `TOO_LONG` (автозаполнение, мобильная клавиатура без `paste`).
- **Страна не следовала за внешним `value`.** Страна вычислялась только в начальном `useState`: после `reset` с номером другой страны селект оставался прежним, в консоли `Expected phone number … to correspond to country …`, правка склеивала номер с чужим кодом. Теперь внешняя смена `value` (не совпадающая с последним значением, отданным в `onChange`) берёт страну из номера. Пустое значение страну не сбрасывает; флаг «страна только что сменена пользователем» синхронизацию подавляет.
- **«Выделить всё → ввести цифру» на полном номере** блокировался `keydown`. Теперь при `selectionStart !== selectionEnd` ввод не блокируется.
- **`value` не в E.164** (`901234567`, `+998-901234567`, `+998 90 123-45-67`) давал ошибку `validateE164Number` и пустое/мусорное поле. Теперь нормализуется для отображения (`normalizePhoneValue`) без вызова `onChange`; неразбираемое — пустое поле без ошибок в консоли.

**Changed**

- Начальная страна выбирается среди разрешённых `countries` (раньше — среди всех поддерживаемых, и селект мог показать страну не из списка).
- `data-filled` у поля отражает показанное значение, а не сырой `value`.

**Tests / Docs**

- `PhoneInput.test.tsx` (компонент), `phoneInputHelpers.test.ts` (хелперы); история `External value (form reset)`; `README.md` компонента с правилами страны и нормализации.
- Страница `PhoneInput` на сайте (ru / en / uz): раздел «Значение и страна» с примером `useController`.

### Решения по реализации

- **Своё значение vs внешнее — через state `knownValue`, а не ref.** Сравнение идёт во время рендера (паттерн «adjusting state when props change», как у существующего флага), а чтение ref в рендере запрещает `eslint-plugin-react-hooks` 7.
- **Неполный E.164 при вводе отдаётся библиотеке как есть**, без разбора страны: `+7912` с выбранным KZ `libphonenumber-js` относит к RU, и разбор скрыл бы набираемый номер.
- **Разбор в `onChange` только для вставки нескольких цифр разом** — иначе одна лишняя цифра на мобильном могла случайно сложиться в «возможный» номер другой страны.

### Проверено

- `vitest`: 23 теста компонента + 21 тест хелперов.
- Storybook в Chromium (Playwright): вставка UZ / RU / национального / частичного номера, вставка поверх номера, ввод без `paste`, выделить всё + цифра, блокировка лишней цифры, внешние `+79123456789` / `+998-901234567` / `901234567` / `""`, правка после сброса, смена страны пользователем — ошибок и предупреждений в консоли нет.
