# [2026-07-29] Hotfix 0.13.1 — висячий `@import` в `dist/style.css` ломал сборку у потребителей

### Что случилось

В 0.13.0 собранный `dist/style.css` начинался с `@import "./tokens.css"`, при этом `dist/tokens.css` в опубликованный пакет **не попадал** (в тарболле только `dist/style.css` и `dist/cjs/style.css`). У потребителей `postcss-import` падал с `ENOENT … tokens.css` — ломались и `dev`, и `build`. Сами токены (`:root`, `--halo-*`, `--motion-duration-halo-*`) в `style.css` присутствовали, то есть импорт был чисто висячим.

Дефект внесён вместе с hover-ореолом (см. [2026-07-29-hover-halo.md](2026-07-29-hover-halo.md)): в новый `src/styles/interactions.module.css` был добавлен `@import './tokens.css'`.

### Причина

`@import` не инлайнится, если он объявлен в `.module.css`, который подключается к компонентам **только через `composes`**. Такой файл Vite проводит через резолвер CSS Modules, минуя обычный конвейер, и импорт всплывает наружу — в общий бандл, где путь `./tokens.css` уже ни на что не указывает.

Проверено, что дело именно в этом, а не в «импорте из своего каталога»: `src/styles/tokens.css` импортирует `./primitives.css` и `./shadows.css`, `BaseInput.module.css` — `./BaseInput.variables.css`, и они инлайнятся нормально. Разница ровно одна — эти файлы подключены обычным путём (через `@import` из модуля, который импортируется из TSX), а `interactions.module.css` виден сборке только по `composes`.

### Почему не поймали

Ни `typecheck`, ни `lint`, ни `test:run`, ни сам `vite build` эту поломку не видят: с точки зрения репозитория сборка успешна, артефакт формально валиден. Проблема проявляется только при установке пакета на стороне потребителя. Релизный чеклист такого шага не содержал.

### Что изменено

**Fixed**

- `src/styles/interactions.module.css` — убран `@import './tokens.css'`. На поведение не влияет: `.halo` переменные только читает, а значения приезжают в `:root` вместе с общим `style.css`. В файле оставлен комментарий с объяснением, чтобы импорт не вернули.

**Infrastructure**

- `scripts/check-dist-css.mjs` — новая проверка: рекурсивно обходит `dist/**/*.css` и падает, если найден `@import` на файл, которого нет в пакете (внешние `http(s)://` игнорируются). Подключена как `postbuild`, то есть выполняется на каждом `npm run build` и, следовательно, перед публикацией.

### Проверка

- Воспроизведено на текущем `dist`: `@import"./tokens.css";` в начале `style.css`, `dist/tokens.css` отсутствует.
- После правки `@import` нет ни в `dist/style.css`, ни в `dist/cjs/style.css`; токены и правила `.halo` на месте, склейка `composes` цела (`_btn_… _halo_…`).
- Страж проверен в обе стороны: на исправленной сборке проходит, на искусственно возвращённой поломке падает с кодом 1 и внятным сообщением.

### Затронутые файлы

- `src/styles/interactions.module.css` — снят импорт, добавлено предупреждение.
- `scripts/check-dist-css.mjs` — **новый**.
- `package.json` — скрипт `postbuild`.
- Публичный changelog — `docs-site/guide/changelog.md` (+ `en/`, `uz/`).

### Как вернуть

`git revert` коммита `fix(build): drop dangling tokens import from dist css`. Возврат вернёт поломку сборки у потребителей — делать только вместе с иным решением.
