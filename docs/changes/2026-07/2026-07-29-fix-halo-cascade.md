# [2026-07-29] Hotfix 0.13.2 — каскад: `.halo` затирал переменные вариантов

### Что случилось

В 0.13.1 у `filled` и `lighter` вместо широкой ауры (кольцо 3px + свечение) применялась базовая кромка 1px. На реальной кнопке `variant="filled" color="primary"` computed `::after` `box-shadow` был `rgb(51, 92, 255) 0 0 0 1px`.

Причина — каскад. Утилита `.halo` и классы вариантов `.filled` / `.lighter` имеют **одинаковую специфичность (0,1,0)**, а в собранном `style.css` утилита оказывается сильно позже вариантов (замерено: Button `.filled` ≈ байт 38 606, `.halo` ≈ байт 120 073). При равной специфичности побеждает то, что ниже по документу, — то есть `.halo`, возвращавший базовые `--halo-ring-size: 1px` и `--halo-glow-color: transparent`.

Дефект внесён вместе с ореолом (см. [2026-07-29-hover-halo.md](2026-07-29-hover-halo.md)). Он тем обиднее, что рядом, в исключении для нейтральной палитры, специфичность была поднята до (0,2,0) **именно из-за этого риска**, и в комментарии стояло «независимо от порядка» — к самим вариантам тот же вывод применён не был.

### Почему не приняты оба предложенных варианта

Потребитель предложил либо поднять `.halo` выше вариантов в порядке вывода, либо дать вариантам `.btn.filled`:

- **порядок вывода** задаёт бандлер: правило починится «случайно» и так же случайно сломается при следующем изменении сборки;
- **`.btn.filled` (0,2,0)** входит в ничью с исключением `.btn:global(.color-neutral)`, которое тоже (0,2,0) и объявлено в файле раньше. Варианты выиграли бы по порядку, и нейтральные `filled` получили бы ауру цвета `--pal-bg-hover` = `--bg-weak-50` = `#f7f7f7` — невидимую на типовом фоне страницы. То есть починка одного варианта ломала бы другой.

### Что сделано вместо

`.halo` больше **не объявляет** `--halo-*` вообще; дефолты перенесены в `var(…, fallback)` внутри `::after`:

```css
.halo {
  position: relative;
}

.halo::after {
  inset: var(--halo-offset, 0px);
  box-shadow:
    0 0 0 var(--halo-ring-size, 1px) var(--halo-ring-color, var(--pal-base, var(--halo-neutral))),
    0 2px 10px -3px var(--halo-glow-color, transparent);
}
```

Объявлять переменную теперь некому, конфликта нет в принципе, и порядок правил перестал что-либо решать. Специфичности при этом сохраняют смысл: варианты (0,1,0) задают свои значения, нейтральное исключение (0,2,0) их перекрывает.

Побочная польза: `--halo-*` стали переопределяться из `:root` в приложении. Раньше объявление на самом элементе било унаследованное значение, и потребителю требовалась специфичность выше `.halo` — этот недочёт был замечен ранее, но отдельно не исправлялся.

### Проверка в живом браузере

Установлен chromium для Playwright (его postinstall падал с начала работы), добавлен `npm run verify:halo` — проверка против собранного `dist/`: берётся реальный `style.css` и реальные хешированные классы из `dist/components/Button/Button.module.css.js`, то есть ровно то, что получает потребитель.

Замеры computed `::after` при наведении:

| Кнопка              | box-shadow                                                                 |
| ------------------- | -------------------------------------------------------------------------- |
| `filled` / primary  | `rgba(71,108,255,.1) 0 0 0 3px, rgb(51,92,255) 0 2px 10px -3px`            |
| `lighter` / primary | `rgba(71,108,255,.1) 0 0 0 3px, rgba(0,0,0,0) …`                           |
| `stroke` / primary  | `rgb(51,92,255) 0 0 0 1px, rgb(51,92,255) 0 2px 10px -3px`                 |
| `ghost` / primary   | `rgb(51,92,255) 0 0 0 1px, rgba(0,0,0,0) …`                                |
| `filled` / neutral  | `rgb(163,163,163) 0 0 0 1px` (= `#a3a3a3`, не совпадает с фоном `#f7f7f7`) |

После увода курсора `opacity` возвращается к `0`. Заодно подтверждён нейтральный тон, который до этого подбирался только по hex-значениям примитивов.

### Почему не поймали раньше

Каскадный дефект не виден ни линтеру, ни типам, ни юнит-тестам, ни сборке: CSS валиден, классы на месте, значения «просто» перекрываются. Единственный способ увидеть — вычисленный стиль в браузере, чего в проверках не было. Теперь есть два уровня: дешёвый инвариант в `postbuild` и полноценная браузерная проверка.
